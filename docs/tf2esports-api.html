API Analysis — tf2esports.com

v1.0.0 OpenAPI 3.0.3 Read-only Invite-only 60 req/min

Documentation construite à partir de la spec Swagger /api/v1/docs/ et de captures réelles de chaque endpoint (clé valide) effectuées le 15 septembre 2026. Les schémas de réponse sont donc observés sur le terrain, pas devinés.

1. Introduction #

API d'analyse (lecture seule) de la plateforme tf2esports : classements (rankings), équipes, joueurs, matchs et statistiques par carte du TF2 compétitif (6v6 & Highlander), tous les ligues/évènements confondus (ETF2L, RGL, ozfortress, Matcha…).

  • Base URL : https://tf2esports.com — chemins préfixés /api/v1
  • Contenu-type : application/json; charset=utf-8
  • Serveur : Node.js/Express derrière Cloudflare (HTTP/2, CSP stricts)
  • Volume de données (capture 15/09/2026) : ~35 059 équipes, ~108 283 joueurs, ~177 932 matchs terminés, ~930 195 statistiques joueur/carte

2. Accès & authentification #

Accès sur invitation : connexion sur tf2esports.com → demander l'accès API depuis les paramètres de compte → une fois approuvé, générer une clé.

La clé s'envoie d'une des deux façons (une seule suffit) :

MéthodeHeaderExemple
Header API-KeyX-API-KeyX-API-Key: tf2_live_…
Bearer tokenAuthorizationAuthorization: Bearer tf2_live_…

Les questions de validité/scopes/limites se règlent avec l'endpoint GET /api/v1 qui décrit la clé. En cas de réutilisation de la réponse, mettre en cache : la clé peut être révoquée ou limitée.

3. Scopes #

Chaque endpoint exige un scope (sauf Meta, ouvert à toute clé valide). Clé sans scope requis → 403.

ScopeEndpoints
rankings/rankings, /rankings/history, /teams/{id}/ranking-history
matches/teams/{id}, /teams/{id}/matches, /matches, /stats/head-to-head
players/players/{id}/stats, /leaderboard
maps/stats/maps
— (clé valide)/api/v1, /stats/meta

Attention : le profil d'équipe (/teams/{id}) est sous scope matches, pas rankings. La clé utilisée pour cette doc déclare les 4 scopes : ["rankings","players","matches","maps"].

4. Conventions & bizarreries de l'API #

4.1 Pagination

page (≥1, défaut 1) et limit (1–100, défaut 50) sur les endpoints listés. Comportements observés :

  • /rankings retourne total (nb d'éléments du board) → pagination calculable.
  • /matches et /teams/{id}/matches n'ont pas de champ total → fin de pagination détectée quand une page retourne [] vide.
  • /rankings, /rankings/history au-delà de la fin : 200 avec rankings: [] (pas d'erreur).
  • /leaderboard et /stats/maps n'ont pas de paramètre page : liste complète en une seule réponse.

4.2 Format & région

ParamètreValeursDéfaut
format 6v6, Highlander 6v6 — excepté /matches où l'omission = non filtré
region North America, Europe, Oceania, Asia, South America
ou nom de ligue : RGL, ETF2L, ozfortress, Matcha…		 — (monde, rangs mondiaux)

Le « region » interne d'une équipe est un nom de ligue (« ETF2L », « ozfortress »), pas une zone géographique. Le filtrage géographique region=Europe est acccepté sur /rankings et /leaderboard et renvoie alors les équipes/joueurs dont la ligue est européenne.

4.3 Date & heures

  • Dates de matchs / snapshots : YYYY-MM-DD.
  • Horodatages : ISO 8601 avec Z, parfois avec millisecondes (2026-09-11T15:00:09.387Z).
  • country est normalisé sans espace : SouthKorea, UnitedStates.

4.4 Typage « mou » (à gérer côté client)

L'API est pour le moins incohérente sur les types — important pour l'import :

  • La plupart des nombres (points, kills, counts, ratios, scores) sont renvoyés comme chaînes décimales : "1914.82", "917". Exceptions réelles : page/limit/total, rangs (world_rank…), matches_counted, best_of, scores de match, longest_killstreak, dpm/kills… de recent, winner_team_id → vrais entiers.
  • Les ID sont des chaînes ("12628") dans la plupart des payloads mais des entiers dans /teams/{id}/matches (team_id) ou winner_team_id. Toujours caster/str-caster avant comparaison.
  • Valeurs null omniprésentes : team_id/team_name/region pour les joueurs sans équipe, scores des matchs non joués, quickfix_ubers/vaccinator_ubers si jamais joués.
  • Le paramètre format n'est pas validé côté serveur : format=Bogus redonne silencieusement le derivé 6v6. Ne pas compter sur une erreur 400.

4.5 Rate limiting

La limite est de 60 requêtes / minute / clé (champ rate_limit_per_min exposé par GET /api/v1). Le dépassement → 429. Comme aucun header de quota/remise à zéro n'est renvoyé en dessous du seuil, garder un intervalle d'au moins ~1 s entre les appels et mettre en cache agressivement.

6. Exemples de code #

6.1 cURL

# Header X-API-Key
curl -H "X-API-Key: votre_cle_ici" \
     "https://tf2esports.com/api/v1/rankings?format=Highlander&region=Europe&limit=100"

# Bearer token
curl -H "Authorization: Bearer votre_cle_ici" \
     "https://tf2esports.com/api/v1/players/8658/stats"

6.2 JavaScript (fetch)

const API_KEY = "votre_cle_ici";
const res = await fetch("https://tf2esports.com/api/v1/matches?team=12628&limit=50", {
  headers: { "X-API-Key": API_KEY },
});
if (!res.ok) {
  const err = await res.json();
  throw new Error(`${res.status}: ${err.message}`);
}
const data = await res.json();

6.3 PHP 8+ (client natif)

$key   = 'votre_cle_ici';
$query = http_build_query(['team' => 12628, 'status' => 'Completed', 'limit' => 100]);

$ctx = stream_context_create([
  'http' => ['ignore_errors' => true, 'header' => "X-API-Key: {$key}\r\n"],
]);

$body = file_get_contents("https://tf2esports.com/api/v1/matches?{$query}", false, $ctx);
$data = json_decode($body, true, 512, JSON_THROW_ON_ERROR);
Pensé pour la suite : les volumes (~178k matchs) interdisent un pull complet en une page. Idéalement, itérer page avec since + status=Completed, mettre en cache les résultats sous hlfr_data_path(), et relancer de manière différentielle au lieu de tout rapatrier.

GET /api/v1/rankings/history Scope : rankings

11. Matches #

GET /api/v1/matches Scope : matches

Recherche de matchs, du plus récent au plus ancien, avec filtres.

Quand format est omis, le résultat est non filtré (les deux formats, à distinguer via le champ format de chaque item). Les matchs à venir (status=Upcoming) sont inclus avec des scores null et des dates futures. Pas de champ total : itérer page jusqu'à obtenir une liste vide.

Paramètres

ParamTypeObl.DéfautDescription
teamintegeropt.—Id d'une équipe impliquée.
eventintegeropt.—Id d'un évènement/saison.
statusstringopt.—Upcoming, Live, Completed, Cancelled.
sincestring (date)opt.—Matchs le YYYY-MM-DD demandé ou après.
formatstringopt.— (non filtré)6v6 | Highlander. Pas de défaut 6v6 ici.
pageintegeropt.1≥ 1.
limitintegeropt.501–100.

Réponse 200 — objet Match (schéma observé)

ChampTypeDescription
idstringId du match.
datestringYYYY-MM-DD.
statusstringUpcoming / Live / Completed / Cancelled.
best_ofintBO du match (1, 3, 5…).
event_idstringId de l'évènement (joignable via param event).
event_namestringNom de la saison (ex. « ETF2L 6v6 Season 52 »).
formatstring6v6 / Highlander — présent seulement sur /matches.
team1_id, team1_name, team2_id, team2_namestringÉquipes (ids en chaîne).
team1_score, team2_scoreint/.nullScores ; null si non joué.
league_match_urlstringLien vers la page du match sur la ligue (ETF2L, RGL…).

GET /api/v1/stats/head-to-head Scope : matches

Face-à-face entre deux équipes (matchs terminés uniquement, jusqu'à 500 confrontations).

Les paramètres limit/page ne sont pas définis pour cet endpoint et sont ignorés : toute l'historique est retournée (plafonnée à 500). team_a décrit « l'équipe A » dans les réponses ; les équipes inconnues → 404 not_found.

12. Maps #

GET /api/v1/stats/maps Scope : maps

Fréquence de jeu des cartes (meilleure pour déceler pic/ban et meta). Matchs terminés uniquement.

Listé par times_played décroissant, toutes les cartes en une réponse (pas de pagination). Le paramètre region filtre par ligue du home team (ozfortress, ETF2L, RGL…) ; omission = toutes ligues.

Paramètres

ParamTypeObl.DéfautDescription
formatstringopt.6v66v6 | Highlander.
regionstringopt.— (toutes)Nom de ligue : ozfortress, ETF2L, RGL…

Réponse 200 (schéma observé)

Racine : maps[] (tri desc par times_played).

ChampTypeDescription
map_idstringId de la carte.
map_namestringNom commun (Process, Product, Ashville…).
map_typestringcontrol_point, king_of_the_hill, payload, capture_the_flag…

matchesstringRedondant avec times_played (même valeur sur la capture).
